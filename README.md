# Gift Upgrades Bot

Telegram-бот, который присылает подарки, **только что улучшенные** до уникальных (NFT-подарки
`t.me/nft/...`): модель, фон, узор, их редкость, номер, владельца, отправителя и цену, если подарок
сразу выставили на продажу. Фильтры собираются в подписки.

## Возможности

* **Несколько подписок** на чат, у каждой свой набор фильтров. Приходит всё, что подходит хотя бы под
  одну. Если подарок подошёл под несколько подписок, в уведомлении видно, под какие именно.
* **Фильтры:** коллекции (включить или исключить), модель, фон, узор (выбор кнопками из реального
  списка коллекции, редкие сверху, или текстом с шаблоном `*`), максимальная редкость каждого атрибута,
  редкость всего сочетания («реже 1 из 10 млн»), максимальный номер, красивые номера (≤100, 777,
  2500, 12321, 1234…), владелец с @username, только на продаже, цена не выше N ⭐.
* **Быстрый старт** из готовых пресетов: редкие модели, красивые номера, сразу на продаже, все подряд.
* **Уведомление:** ссылка с превью подарка, все атрибуты с процентами, редкость сочетания, владелец и
  кнопка на его профиль, кто подарил, цена в ⭐/TON, оценка в $, пометка крафта. Кнопка «🔕 Не
  присылать коллекцию» с отменой в одно нажатие.
* **Без спама:** если подарков много, они собираются в одну сводку (редкие сверху). Частоту можно
  выбрать: мгновенно, раз в минуту, 5, 15 или 60 минут. Лимиты Bot API соблюдаются.
* **`/recent`** — последние улучшения по вашим подпискам; **`/top`** — самые редкие сочетания за
  сутки; **`/stats`** — самые активные коллекции (админам ещё и служебные метрики).
* **Работает в группах:** настройки там меняют только админы чата.

## Как это работает

Bot API не отдаёт ленту улучшений, поэтому есть два компонента:

* **Наблюдатель** — обычный аккаунт Telegram (Telethon/MTProto). Уникальные подарки нумеруются по
  порядку (`PlushPepe-1`, `PlushPepe-2`, …), и каждый сообщает, сколько экземпляров уже выпущено
  (`availability_issued`). Все номера между последним известным и текущим — новые улучшения.
  * Опрос **адаптивный**: коллекции, где только что были улучшения, проверяются каждые несколько
    секунд, тихие — всё реже (до полутора минут).
  * Общий **ограничитель скорости** сам снижает темп после FloodWait и потом восстанавливает его.
  * **Слаг коллекции** угадывается из названия, а если не подошёл, берётся настоящий с маркета
    подарков. Ручная правка не нужна.
  * Большой отрыв (например, после перерыва) **догоняется порциями без пропусков**. Номер, который
    так и не стал доступен, пропускается после нескольких попыток и не блокирует коллекцию.
  * Списки моделей, фонов и узоров каждой коллекции подгружаются фоном для кнопок в фильтрах.
  * Если сессия аккаунта слетела, админам приходит сообщение.
* **Бот** (aiogram 3) хранит подписки в SQLite и рассылает подходящие подарки.

При первом запуске история не рассылается: бот запоминает текущие номера и дальше присылает только
новое. После перезапуска он продолжает с того же места.

## Запуск локально

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # заполните BOT_TOKEN, API_ID, API_HASH, ADMINS
python -m giftbot.login     # один раз: вход в аккаунт-наблюдатель (код из Telegram)
python -m giftbot
```

* `BOT_TOKEN` — от [@BotFather](https://t.me/BotFather).
* `API_ID` / `API_HASH` — с [my.telegram.org](https://my.telegram.org). Для наблюдателя лучше завести
  отдельный аккаунт.
* `ADMINS` — ваш Telegram ID: служебная статистика и уведомления о проблемах.

Остальные настройки (скорость опроса, срок хранения истории и т.д.) описаны в `.env.example`.

> ⚠️ Не запускайте одну и ту же сессию в двух местах одновременно (например, локально и в Actions):
> Telegram сочтёт это компрометацией и отключит её (`AuthKeyDuplicated`).

## Запуск на GitHub Actions

Workflow `.github/workflows/bot.yml` держит бота запущенным: каждый запуск работает ~5 ч 45 мин,
сохраняет базу в кэш Actions и сам запускает следующий. Между запусками бывает пауза в пару минут.
Пропущенные за это время улучшения бот догонит после старта.

1. Локально выполните `python -m giftbot.login` и скопируйте напечатанный `SESSION_STRING`.
2. В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret**
   и добавьте `BOT_TOKEN`, `API_ID`, `API_HASH`, `SESSION_STRING`, `ADMINS`.
3. Откройте **Actions → bot → Run workflow**.

Пока секреты не заданы, запуски по расписанию просто пропускаются с предупреждением.
Учтите: GitHub не рассчитан на постоянные сервисы в Actions, и правила это формально запрещают.

## Docker

```bash
docker build -t giftbot .
docker run -d --restart=unless-stopped --env-file .env -v giftbot-data:/data giftbot
```

Сессию можно передать через `SESSION_STRING` в `.env` или положить файл `watcher.session` в том `/data`.

## Разработка

```bash
pip install -r requirements-dev.txt
ruff check . && ruff format --check . && pytest -q
```

Тесты имитируют Telegram с обеих сторон (MTProto и Bot API): проверяют поиск улучшений, догон,
пропуски и поиск слага, все экраны меню (обходом каждой кнопки), рассылку, сводки и запуск
целиком. Те же проверки гоняет `.github/workflows/tests.yml` на каждый push.
