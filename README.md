# Gift Upgrades Bot

Telegram-бот, который следит за подарками Telegram:

* 🆕 присылает подарки, **только что улучшенные** до уникальных (NFT-подарки `t.me/nft/...`);
* 🏷 ловит **новые лоты на маркете** и лоты **дешевле флора** (режим «снайпер»);
* 👁 следит за **конкретными подарками** (продажа, смена владельца, цена) и **людьми**.

Фильтры собираются в подписки. Подписку можно присылать в личку, в группу или в свой канал.

## Возможности

**Подписки и фильтры.** В чате может быть несколько подписок, у каждой свои фильтры. Приходит всё,
что подходит хотя бы под одну.

* **События:** улучшения и/или новые лоты на продаже.
* **Коллекции:** включить или исключить.
* **Модель, фон, узор:** выбор кнопками из реального списка коллекции (редкие сверху) в режиме
  «только эти» или «кроме этих». Можно и текстом, с шаблоном `*`.
* **Редкость:** максимальная редкость каждого атрибута и редкость всего сочетания («реже 1 из 10 млн»).
* **Номер:** максимальный номер, красивые номера (≤100, 777, 2500, 12321, 1234…), свои номера и
  диапазоны (`1, 69, 777, 1000-1100`).
* **Цена:** только на продаже, цена не выше N ⭐, **дешевле флора минимум на X%**.
* **Люди:** владелец с @username, конкретные люди по @username или id (как владелец или отправитель).

**Быстрый старт.** Готовые пресеты: редкие модели, красивые номера, сразу на продаже,
снайпер «дешевле флора», все подряд.

**Уведомления.**

* **Улучшение:** превью подарка, атрибуты с процентами, редкость сочетания, владелец, кто подарил,
  цена в ⭐/TON и скидка от флора, оценка в $, пометка крафта.
* **Лот на продаже:** цена, «−33% от флора», атрибуты, продавец, кнопка «🛒 Купить».
* **Кнопки под уведомлением:** «👁 Следить за подарком», «👤 Следить за ним», «🔕 Не присылать
  коллекцию» (с отменой).
* **Без спама:** пачка событий приходит одной сводкой, самые редкие или выгодные сверху. Частоту
  выбираете сами: мгновенно, раз в минуту, раз в 5, 15 или 60 минут.

**Слежка.**

* `/watch t.me/nft/...` — бот пришлёт, если подарок продан, сменился владелец, его выставили или сняли
  с продажи, изменилась цена или подарок сожгли.
* Ссылка на подарок в личке — бот покажет всё о нём.

**Отчёты.**

* `/recent` — последнее по вашим подпискам.
* `/top` — самые редкие сочетания за сутки.
* `/deals` — самые выгодные лоты за сутки.
* `/collection Plush Pepe` — темп улучшений, прогноз окончания лимита, флор, частые модели и PNG-график.
* `/daily` — ежедневная сводка в выбранное время.
* `/stats` — самые активные коллекции; админу ещё и служебные метрики.

**Каналы.** Добавьте бота админом в свой канал и выполните `/connect @канал`. После этого любую
подписку можно присылать туда.

**Группы.** Бот работает и в группах; настройки там меняют только админы чата.

**Inline-режим.** `@имя_бота pepe gold` в любом чате ищет по недавним улучшениям и вставляет карточку
подарка.

**Mini App.** Кнопка «🖥 Редактор» открывает удобную страницу с поиском по коллекциям и всеми
фильтрами сразу. Нужен `WEBAPP_URL`, см. ниже.

**Премиум за Telegram Stars.** Включается, если задать `PREMIUM_PRICE`. Бесплатно — несколько подписок
и подарков в слежке. В премиуме — больше подписок, лента продаж и снайпер, автопостинг в каналы.
Оплата встроена в Telegram, есть возврат звёзд через `/refund` (для админа). Пока `PREMIUM_PRICE=0`,
всё бесплатно.

**Админу.**

* Уведомления о слетевших сессиях аккаунтов.
* Ежедневный бэкап базы в личку и `/backup`.
* `/broadcast текст` — рассылка всем пользователям.

## Как это работает

Bot API не отдаёт ни ленту улучшений, ни маркет, поэтому основную работу делают **аккаунты-наблюдатели**:
обычные аккаунты Telegram через Telethon/MTProto. Сам бот (aiogram 3) хранит подписки в SQLite и
рассылает подходящее.

* **Улучшения.** Уникальные подарки нумеруются по порядку (`PlushPepe-1`, `-2`, …), и каждый сообщает,
  сколько экземпляров уже выпущено. Все номера между последним известным и текущим — новые
  улучшения.
  * Опрос адаптивный: где только что были улучшения — каждые 4 с, тихие коллекции — всё реже.
  * Большой отрыв догоняется без пропусков.
  * Слаг коллекции, если не угадался из названия, берётся с маркета.
* **Маркет.**
  * Один запрос раз в 30 с даёт флор и число лотов по всем коллекциям сразу.
  * Если у коллекции что-то изменилось, бот смотрит её ленту продаж и находит новые лоты. Ленты
    смотрятся только для коллекций, которые нужны чьим-то подпискам.
  * Скидка считается от флора до появления лота.
* **Пул аккаунтов.** Аккаунтов-наблюдателей может быть несколько: нагрузка делится между ними.
  * FloodWait на одном аккаунте переключает запросы на другие.
  * Если сессия слетела, аккаунт выбывает, а админу приходит сообщение.

При первом запуске история не рассылается: бот запоминает текущее состояние и дальше присылает только
новое. После перезапуска продолжает с того же места.

## Запуск локально

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # заполните BOT_TOKEN, API_ID, API_HASH, ADMINS
python -m giftbot.login     # один раз: вход в аккаунт-наблюдатель (код из Telegram)
python -m giftbot
```

* `BOT_TOKEN` — от [@BotFather](https://t.me/BotFather).
* `API_ID` / `API_HASH` — с [my.telegram.org](https://my.telegram.org). Для наблюдателей лучше завести
  отдельные аккаунты.
* `ADMINS` — ваш Telegram ID.
* **Несколько аккаунтов** — быстрее и устойчивее к FloodWait. Выполните
  `SESSION=watcher2 python -m giftbot.login` и перечислите строки сессий в `SESSION_STRING` через пробел
  (или файлы в `SESSION=watcher,watcher2`).
* **Inline-режим** включается у @BotFather: `/setinline`.

Остальные настройки описаны в `.env.example`.

> ⚠️ Не запускайте одну и ту же сессию в двух местах одновременно (например, локально и в Actions):
> Telegram сочтёт это компрометацией и отключит её (`AuthKeyDuplicated`).

## Mini App (редактор фильтров)

Страница лежит в `docs/index.html`. Она статическая, все данные передаются в ссылке, сервер не нужен.

1. **Settings → Pages:** выберите *Deploy from a branch*, ветку `master`, папку `/docs`.
2. Через минуту страница будет по адресу `https://<логин>.github.io/<репозиторий>/`. Укажите его в
   `WEBAPP_URL`: в `.env` или в **Settings → Secrets and variables → Actions → Variables**.

## Запуск на GitHub Actions

Workflow `.github/workflows/bot.yml` держит бота запущенным. Каждый запуск работает ~5 ч 45 мин,
сохраняет базу в кэш Actions и сам запускает следующий. Между запусками бывает пауза в пару минут;
улучшения за это время бот догонит после старта.

1. Локально выполните `python -m giftbot.login` и скопируйте напечатанный `SESSION_STRING`.
2. Откройте **Settings → Secrets and variables → Actions → Secrets** и добавьте `BOT_TOKEN`, `API_ID`,
   `API_HASH`, `SESSION_STRING`, `ADMINS`.
3. Необязательно: во вкладке **Variables** задайте `WEBAPP_URL`, `TIMEZONE`, `PREMIUM_PRICE`,
   `PREMIUM_DAYS`, `SLUG_OVERRIDES`.
4. Откройте **Actions → bot → Run workflow**.

Пока секреты не заданы, запуски по расписанию просто пропускаются с предупреждением.
Учтите: GitHub не рассчитан на постоянные сервисы в Actions, и правила это формально запрещают.

## Сервер (VPS)

**Docker:**

```bash
docker compose up -d --build      # бот перезапускается сам; база в томе giftbot-data
```

**systemd** (без Docker): см. `deploy/giftbot.service`.

**Перенос базы с Actions:** админ присылает себе `/backup` и кладёт файл на сервер как `DB_PATH`.

## Разработка

```bash
pip install -r requirements-dev.txt
ruff check . && ruff format --check . && pytest -q
```

Тесты имитируют Telegram с обеих сторон (MTProto и Bot API). Они проверяют:

* поиск улучшений, догон, пропуски и поиск слага;
* маркет и скидки, слежку, пул аккаунтов;
* все экраны меню обходом каждой кнопки;
* каналы, inline, Mini App, оплату Stars, расписание, бэкапы;
* запуск целиком.

Те же проверки гоняет `.github/workflows/tests.yml` на каждый push.
